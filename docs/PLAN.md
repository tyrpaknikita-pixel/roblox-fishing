# План базовой игры — 2026-09-28

Статус на 2026-10-01: этапы 1–6 выполнены и проверены; актуальные результаты и ограничения находятся в STATE.md. Этап 7 остаётся следующим этапом разработки.

## Подтверждённый исходный статус
В fishing.rbxl есть FishingWorld (108 потомков) в Edit, но нет игровых скриптов. Terrain на Y=10 перекрывает воду Y=-2 и часть декораций. Старый bootstrap удаляет мир при повторном запуске; ручные перемещения теряются.

## Требования
- Постоянный мир существует до Play: именованные Model/Part, которые можно выбирать и перемещать.
- Водоём — Model с Water, Pier и стабильным ZoneId. Логика читает актуальное положение Water.
- Обновление кода сохраняет ручные перемещения. Bootstrap выполняется только явно в Edit, никогда как runtime Script.
- В Play появляются только временные поплавки, лески, эффекты и интерфейс.
- Не очищать пользовательский Terrain. До миграции сделать резервную копию.

## Этапы и критерии готовности
1. **Редактор.** Устранить перекрытие Terrain, защитить bootstrap от Play/разрушительной пересборки. Проверить видимость в Edit, сохранение перемещений после обновления/Stop.
2. **Окружение.** Спокойный стилизованный рыболовный парк: голубая лагуна, зелёный пруд, фиолетовый водоём; причалы, тропинки, растения, камни, навесы, лавка. Отдельные цветные поверхности воды.
3. **Рыбалка.** Удочка → заброс возле воды → видимый поплавок и леска → поклёвка → подсечка → конкретная рыба в корзине → продажа. Сервер проверяет снасть, расстояние, состояние и время; смерть/снятие удочки отменяют заброс.
4. **Снасти.** Три уровня удочки, три поплавка, три вида приманки с запасом и расходом. Покупка за игровые монеты, без Robux. Эффекты отражаются в UI и механике.
5. **Рыбы.** Минимум девять видов (три на водоём), стоимость, вес, редкость, таблицы по ZoneId. Снасти влияют на процесс или улов.
6. **Проверка.** Успех, ранняя/поздняя подсечка, покупка, нехватка денег, выбор снасти, расход приманки, продажа без дублей, все три водоёма. Stop → Save → проверка timestamp → STATE.md.
7. **Следующий этап.** Сохранение между входами с обработкой ошибок загрузки; баланс, мобильная проверка, дополнительные модели. Не выдавать это за реализованное.

## Экономия лимита
Ограниченные задачи (аудит, каталог, UI по согласованному протоколу) поручать GPT-6 Sol Low. Один владелец каждого файла; только основной агент изменяет Studio. Проверять завершённые сценарии, ждать сообщения подагентов без частого опроса.

## Модели
Blender MCP можно добавить после установки Blender и проверки совместимости аддона. Базовая игра от него не зависит. Модели должны иметь логические отдельные части и удобные pivots. Избегать узнаваемых логотипов крупных компаний.
Запрета использовать лицензированные модели нет. Для заимствованных ассетов фиксировать источник и условия. Некоммерческий статус сам по себе не отменяет условия лицензии.
